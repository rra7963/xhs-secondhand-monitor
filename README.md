# XHS Secondhand Monitor

面向小红书公开搜索结果的二手商品线索监测工具。项目基于 Python 与 DrissionPage 驱动本地 Chromium 会话，按固定周期检索最新内容，并对命中线索执行桌面提醒与本地归档。

> 项目当前定位为个人效率工具与自动化实践示例，适合低频、人工监督的本地运行场景。

## 项目定位

XHS Secondhand Monitor 将浏览器自动化、规则过滤、状态去重与本地通知组合为一条轻量线索发现链路。它不依赖云端服务，也不会上传浏览器会话或监测结果。

## 核心能力

- **最新内容优先**：进入搜索结果后主动尝试切换至“最新”排序。
- **组合规则过滤**：以目标词、动作词和排除词构成可解释的判定规则。
- **时间窗口校验**：对详情页发布日期执行 30 天窗口检查。
- **线索状态去重**：从历史结果中恢复已处理的笔记 ID。
- **双通道反馈**：同时提供系统桌面通知与 UTF-8 文本归档。

## 工作流

```text
关键词轮询 → 加载搜索页 → 锁定最新排序 → 扫描首屏 12 条
    → 组合词匹配 → 排除词过滤 → 发布日期校验
    → 桌面通知 + 本地归档 → 随机退避 → 下一轮
```

## 运行架构

程序以单进程常驻循环运行：DrissionPage 负责浏览器生命周期与页面交互，规则层负责文本判定，`plyer` 负责跨平台通知，文件系统负责保存轻量状态。模块之间保持直接的数据流，便于在小型本地部署中观察与调整。

### 最新排序策略

每次关键词检索都会携带 `sort=new` 参数，并在页面加载后再次尝试打开筛选菜单、点击“最新”。双重策略用于降低页面默认排序变化带来的影响；最终排序仍以页面实际展示结果为准。

### 组合匹配策略

候选文本必须同时命中至少一个 `TARGET_WORDS` 目标词和至少一个 `ACTION_WORDS` 动作词，才会进入详情校验。该规则比单关键词命中更容易解释，也更适合按业务语义扩展。

### 排除规则

若候选文本包含 `EXCLUDE_WORDS` 中的求购、推荐或交流群语义，程序会将其标记为已处理并跳过，减少与二手出售信号无关的提醒。

### 去重机制

启动时，程序会从结果文件中的 `explore/<note_id>` 链接恢复历史 ID 集合。当前运行周期内，新处理的 ID 也会立即加入内存集合，从而避免重复判定与重复提醒。

### 时间窗口

详情页日期会被规范化后执行 30 天窗口判断。“刚刚”“分钟”“小时”“昨天”和“天前”等相对时间会被视为窗口内；无法解析的日期会保守放行，并在结果中保留原始值供人工确认。

### 通知与归档

线索通过全部规则后，程序会调用系统通知接口显示标题摘要，并将发现时间、页面日期、内容标题及详情链接追加写入本地结果文件。两种反馈相互独立，便于即时响应与事后复盘。
