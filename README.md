# XHS Secondhand Monitor

面向小红书公开搜索结果的二手商品线索监测工具。项目基于 Python 与 DrissionPage 驱动本地 Chromium 会话，按固定周期检索最新内容，并对命中线索执行桌面提醒与本地归档。

> 项目当前定位为个人效率工具与自动化实践示例，适合低频、人工监督的本地运行场景。

## 项目定位

XHS Secondhand Monitor 将浏览器自动化、规则过滤、状态去重与本地通知组合为一条轻量线索发现链路。它不依赖云端服务，也不会上传浏览器会话或监测结果。

## 核心能力

- **最新内容优先**：进入搜索结果后主动尝试切换至“最新”排序。
- **组合规则过滤**：以目标词、动作词和排除词构成可解释的判定规则。
- **时间窗口校验**：对详情页发布日期执行 30 天窗口检查。
- **线索状态去重**：从历史结果中恢复已处理的笔记 ID。
- **双通道反馈**：同时提供系统桌面通知与 UTF-8 文本归档。

## 工作流

```text
关键词轮询 → 加载搜索页 → 锁定最新排序 → 扫描首屏 12 条
    → 组合词匹配 → 排除词过滤 → 发布日期校验
    → 桌面通知 + 本地归档 → 随机退避 → 下一轮
```

## 运行与停止

监测循环会依次处理三个默认搜索词，并在一轮结束后等待 600–900 秒。需要停止时，在运行终端按 `Ctrl+C`；下次启动会基于结果文件恢复已归档 ID，但仅存在于内存且未写入结果文件的跳过项不会跨进程保留。

## 快速开始

```bash
python main.py
```

程序启动后会创建或复用当前目录下的 `xhs_profile/` 浏览器配置目录，并依次轮询预设搜索词。保持终端窗口运行即可持续监测。

### 首次登录

首次运行时，请在自动打开的浏览器窗口中自行完成小红书登录。登录状态保存在本地 `xhs_profile/`，后续启动通常可以复用；若平台要求重新验证，请按页面提示操作。

## 配置参考

当前版本采用源码内配置。编辑 `main.py` 顶部的常量后重启程序，即可使新规则生效。

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `TARGET_WORDS` | 电视、显示器、机、投影 | 定义目标商品语义 |
| `ACTION_WORDS` | 出、自用、二手等 | 定义出售或处置语义 |
| `EXCLUDE_WORDS` | 求购、想买、求推荐等 | 过滤非出售信号 |
| `CHECK_INTERVAL` | 600–900 秒 | 设置轮询随机等待区间 |
| `RESULT_FILE` | `最新排序_实时监控.txt` | 设置本地结果文件 |

### 关键词设计

建议将目标词保持为明确的品类或型号，将动作词限定为出售意图，并把求购、讨论、推荐等语义放入排除词。词表越宽，召回率通常越高，但误报也会相应增加。

### 轮询间隔

`CHECK_INTERVAL` 是包含上下界的秒数元组。程序会在每轮结束后随机取值，以避免形成完全固定的访问节奏。建议根据实际需求使用分钟级间隔，不要设置为高频请求。

## 本地数据

运行数据仅保存在项目当前工作目录：

- `xhs_profile/`：浏览器用户数据与登录会话。
- `最新排序_实时监控.txt`：已命中线索及其详情链接。

两者均已写入 `.gitignore`，不会被常规 Git 提交纳入版本控制。

### 结果格式

每条命中记录由三部分组成：发现时间与页面日期、截断后的标题摘要、可直接访问的详情链接。示例：

```text
【发现】:09-04 14:30 | 【日期】:09-04 | 示例标题
【链接】:https://www.xiaohongshu.com/explore/<note_id>
------------------------------------------------------------
```

## 运行架构

程序以单进程常驻循环运行：DrissionPage 负责浏览器生命周期与页面交互，规则层负责文本判定，`plyer` 负责跨平台通知，文件系统负责保存轻量状态。模块之间保持直接的数据流，便于在小型本地部署中观察与调整。

### 最新排序策略

每次关键词检索都会携带 `sort=new` 参数，并在页面加载后再次尝试打开筛选菜单、点击“最新”。双重策略用于降低页面默认排序变化带来的影响；最终排序仍以页面实际展示结果为准。

### 组合匹配策略

候选文本必须同时命中至少一个 `TARGET_WORDS` 目标词和至少一个 `ACTION_WORDS` 动作词，才会进入详情校验。该规则比单关键词命中更容易解释，也更适合按业务语义扩展。

### 排除规则

若候选文本包含 `EXCLUDE_WORDS` 中的求购、推荐或交流群语义，程序会将其标记为已处理并跳过，减少与二手出售信号无关的提醒。

### 去重机制

启动时，程序会从结果文件中的 `explore/<note_id>` 链接恢复历史 ID 集合。当前运行周期内，新处理的 ID 也会立即加入内存集合，从而避免重复判定与重复提醒。

### 时间窗口

详情页日期会被规范化后执行 30 天窗口判断。“刚刚”“分钟”“小时”“昨天”和“天前”等相对时间会被视为窗口内；无法解析的日期会保守放行，并在结果中保留原始值供人工确认。

### 通知与归档

线索通过全部规则后，程序会调用系统通知接口显示标题摘要，并将发现时间、页面日期、内容标题及详情链接追加写入本地结果文件。两种反馈相互独立，便于即时响应与事后复盘。

## 环境要求

- Python 3.9 或更高版本
- 可用的 Chromium 内核浏览器
- 支持小红书网页端访问的网络环境
- 支持系统通知的桌面操作系统

## 安装

建议使用独立虚拟环境，避免依赖与系统 Python 相互影响。

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
```
